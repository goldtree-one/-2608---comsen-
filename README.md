Task 2：OpenCV 与 Pillow 图像处理
本部分主要练习图像处理和视频分析的基本方法，包括图片操作、轮廓提取、运动目标检测和视频目标追踪。
2.1 图像读取与通道分离

使用 OpenCV 和 Pillow 读取并显示图片，对图像的三个颜色通道进行分离，并分别保存为灰度图，以观察不同通道所包含的图像信息。

2.2 图像基本变换

实现图像缩放、旋转、平移和翻转等操作。考虑到缩放比例、旋转角度等参数可能因图片而异，程序将相关参数设置为可输入的变量，方便根据实际需要调整。

2.3 图像轮廓提取

在飞机轮廓提取过程中，最初尝试直接进行二值化处理，但由于飞机与背景之间的颜色和亮度差异不够明显，部分轮廓难以有效提取。
后续改用 HSV 颜色空间进行辅助分割，通过颜色条件区分天空与非天空区域，再结合反色、轮廓提取和最大轮廓筛选等操作，尽可能提取飞机主体。随后对轮廓内部进行填充，并从原图中提取内部线条、处理外部边缘，改善最终的轮廓效果。

2.4 运动目标检测

使用帧差法和 MOG2 背景减除法对视频中的运动目标进行检测，并将两种方法的处理结果拼接，方便直观比较。
实验中，MOG2 通过建立和更新背景模型来区分背景与运动区域。在当前测试视频中，使用 MOG2 的结果整体性较好，但实际效果仍然会受到背景变化、光照和运动目标特征的影响。
2.5 视频目标追踪
使用 OpenCV 的追踪器对视频中的小球进行追踪。程序读取视频并获取基本信息，将追踪区域转换为统一格式，再通过人工框选或预设坐标确定初始目标。
在部分视频的测试中，出现了追踪框明显偏移的问题。这说明传统追踪器对初始框选、目标外观变化以及运动过程中的遮挡较为敏感，后续仍需要针对具体视频调整追踪方法和参数。

三、Task 3：PyTorch 函数拟合与手写数字识别
本部分主要使用 PyTorch 进行数值拟合和神经网络分类，熟悉模型构建、损失计算、反向传播和参数更新的基本过程。

3.1 基于梯度下降的函数拟合

使用 PyTorch 的自动求导机制和梯度下降方法，对带有随机噪声的数据进行拟合。
主要流程如下：
使用固定随机种子生成数据，保证相同配置下实验具有较好的可复现性。
在指定区间内生成输入数据，并根据真实函数计算输出，再添加随机噪声。
对数据进行中心化处理，减小较大常数项对数值计算的影响。
使用 `nn.Module` 构建模型，将待拟合的参数定义为可学习参数。
使用均方误差（MSE）作为损失函数，通过反向传播计算梯度，并利用优化器更新参数。
记录训练过程中的损失变化，绘制拟合结果与真实函数的对比图。
根据拟合结果计算决定系数 (R^2)，用于评价模型对数据变化的解释程度。

训练过程中还对损失值进行有限数检查，避免出现数值异常时继续更新参数。

3.2 基于 MLP 的 MNIST 手写数字识别

使用 PyTorch 构建多层感知机（MLP），完成手写数字图像的分类识别。
首先读取数据文件，对图像字节进行解码，并检查图像尺寸和标签格式。将每张 (28\times28) 的灰度图像转换为模型需要的张量形式，再输入神经网络进行训练。
模型使用全连接层提取特征，通过 ReLU 激活函数引入非线性，并输出各个数字类别对应的预测分数。训练时使用交叉熵损失函数（`CrossEntropyLoss`），根据预测结果和真实标签计算误差，再通过反向传播更新网络参数。
为了观察模型的训练效果，将数据划分为训练集、验证集和测试集，并记录训练过程中的损失与准确率。在验证过程中保留表现较好的模型参数，最后对测试数据进行评估，并对部分手写数字的识别结果进行可视化。
本部分主要关注模型能否正确学习图像特征，以及训练过程中的损失和准确率如何变化。

四、Task 4：基于 YOLO 的无人机目标检测与模型量化

本部分选择题目中的第一个方向，使用 YOLO 对无人机目标进行检测和追踪，并进一步比较不同模型导出和量化方式对推理性能的影响。

4.1 公共工具与数据检查

task4_common` 作为项目中的公共工具模块，主要负责素材目录定位、模型权重加载、IoU 计算、JSON 数据保存和推理速度统计等工作，减少不同脚本之间的重复代码。
在数据预处理阶段，程序逐一检查图片及对应的标签文件，验证标签内容和字段格式，并对多边形标注进行矩形框转换，为后续模型训练准备数据。
数据检查还用于发现图片、标签或类别信息中可能存在的问题，避免不符合预期的数据影响训练过程。

4.2 YOLO 预训练模型推理

使用 YOLO 官方预训练模型，对指定的无人机相关图片进行推理，并保存检测结果。

推理过程中主要涉及以下参数：

source：需要检测的图片、视频或其他受支持的输入来源。
conf：置信度阈值，用于过滤低置信度的检测结果。
imgsz：模型推理时使用的输入图像尺寸。
save：是否保存带有检测标注的可视化结果。

程序同时整理检测结果中的相关数值，并以 JSON 格式保存，方便后续分析和比较。

4.3 无人机视频检测与追踪

使用 YOLO 对无人机飞行视频逐帧进行检测，并通过 `model.track()` 实现连续视频帧中的目标追踪。
其中，`persist=True` 用于在连续帧之间保留追踪状态，使模型能够尝试将不同帧中检测到的目标关联起来。
为了进一步分析追踪效果，程序记录目标追踪 ID、每帧检测到的目标数量、上一帧的检测框以及相邻帧检测框之间的 IoU 等信息。
IoU 用于衡量两个检测框的重叠程度，可以辅助分析相邻帧中目标位置的变化，但不能单独作为追踪准确率的完整评价指标。

4.4 模型训练与评估
使用提供的 `drone.pt` 权重进行无人机目标检测模型的训练，并对训练结果进行评估。
训练结束后，整理训练过程中的损失曲线、准确率相关图表以及混淆矩阵等结果，并统计模型的主要检测指标。
本部分涉及的指标包括：
Loss，Precision，Recall，AP，mAP
混淆矩阵

4.5 ONNX 导出与模型量化

在完成基础模型训练与评估后，进一步尝试将模型导出为 ONNX 格式，并比较 FP32、FP16 和 INT8 等不同精度配置下的表现。

其中：

FP32：使用 32 位浮点数表示模型参数和相关计算数据，通常作为基础精度对照。
FP16：使用 16 位浮点数表示相关数据，在受支持的硬件和推理后端上有望减少存储开销并提高推理速度。
INT8：使用 8 位整数表示量化数据，能够进一步降低模型存储和计算开销，但可能带来检测精度损失。
ONNX：一种用于表示和交换机器学习模型的格式，可配合兼容的推理后端进行部署。

实验主要比较模型文件大小、推理速度 FPS，以及量化后检测结果相对于原始模型的变化。

实验结果

5.1 模型导出与量化对比

根据现有实验记录，整理出的结果如下：

| 模型格式         | 模型大小  | FPS | 相对原模型的速度 |
| ------------ | ----- | --- | -------- |
| PyTorch FP32 | 10 MB | 40  | 100%     |
| ONNX FP32    | 9 MB  | 45  | 112.5%   |
| ONNX FP16    | 6 MB  | 50  | 125%     |
| ONNX INT8    | 4 MB  | 42  | 105%     |

注：以上为当前记录中的实验数据。正式提交前应根据实际测试环境、最终模型文件和重复测试结果进行核对。

从现有记录来看，ONNX FP32 的模型大小略小于 PyTorch FP32，推理速度也有所提高。ONNX FP16 的记录速度最高，而 ONNX INT8 的文件最小，但速度并未超过 FP16。

这说明模型量化并不意味着推理速度一定会随精度降低而持续提高。实际性能还会受到推理后端、硬件支持、算子实现和运行环境等因素影响。

另外，当前记录中的检测效果比例需要进一步确认其具体计算方法。如果这些比例代表检测精度的相对变化，应使用相同测试数据和评价指标重新计算，并与原始模型进行比较，避免将模型精度变化与推理速度变化混为一谈。
